# Order API



All endpoints require `Authorization: Bearer <secretKey>` and `X-Api-Key: <publicKey>`. Every POST also requires `Content-Type: application/json` and `X-Signature`, calculated from the complete request body using your `checksumKey`. Recalculate the signature whenever the body changes. See [signature generation](/developers/signature). GET requests do not require `X-Signature`. Data is scoped to your institution and the API key’s test/live mode.

<br />

**Order and return flow**

Create an eSIM or physical SIM order with `POST /api/v1/orders`; use `/orders/recharge` for data recharge. Save `orderId`, `trackId` and each `subOrderId`. Query `GET /orders/:id` or receive [webhooks](/webhooks) to follow updates.

Order `status` is separate from return progress. A successfully fulfilled order stays `SUCCESS` during and after a return. Track returns using `returnStatus`, `hasPendingReturn`, `hasRefundingReturn`, `refundAmount`, `items[].quantityReturned` and `returns[]`. Only new physical SIM orders can be canceled; completed orders use the [Return Request API](/api-list/return-request).

## Create order API

The wallet must be eligible and have sufficient spending capacity. Physical SIM orders require an address and phone number configured on the institution. Shipping information is taken from that profile.

## Recharge data onto the SIM card

Send a unique `trackId` and exactly one item with `subTrackId`, a `SIM_RECHARGE` SKU and `iccids` containing 1–50 unique ICCIDs. Quantity is derived from the ICCID count; do not send `quantity`. China Telecom plans support only one ICCID. A successful response has the same structure as order creation, with `status: SUCCESS` on the order and item, and `type: SIM_RECHARGE`.

## Cancel order API

Only physical SIM orders with order status `NEW`, where every item is of type `SIM` and has status `NEW`, can be canceled. `orderId` is the SimplifyTrip order ID or `trackId`. `reason` is optional. Cancellation sets the order and items to `CANCELED` and restores the order total to the wallet. Ineligible orders return 404.

## Errors and HTTP status

GET succeeds with HTTP 200. POST endpoints currently return HTTP 201. Handle successful 2xx responses. Validation errors or duplicate references can return 400; missing products/orders or ineligible cancellations return 404; product, shipping or wallet eligibility failures return 422; a busy service can return 503.
