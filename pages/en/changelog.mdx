## What's New? 👋
System change log

##### Version 1.4.0 (September 12, 2026)

- ✅ Updated the [Return Request API](/api-list/return-request): use a separate `returnTrackId` for each return and select individual items by physical SIM quantity or eSIM/data-plan ICCIDs. The system determines whether the return is full (`FULL`) or partial (`PARTIAL`).
- ✅ Updated the return flow to `REQUESTED → REFUNDING → COMPLETED`, with `REJECTED` and `CANCELED` outcomes. Only `REQUESTED` requests can be canceled; each order can have only one pending or refunding request at a time.
- ✅ Separated return progress from order status. Successfully fulfilled orders remain `SUCCESS`; the [Order API](/api-list/order) provides tracking through `returnStatus`, `hasPendingReturn`, `hasRefundingReturn`, `quantityReturned`, `refundAmount`, `totalBeforeRefund` and the `returns` history.
- ✅ Updated the `RETURN_ORDER_UPDATE` webhook payload with return references, original order references, item details and refund information. Completion events use `COMPLETED` status. 
 
##### Version 1.3.0 (Mar 24, 2026)
- ✅ Added a new `/orders/recharge` API to Top-up data onto SIM cards.
- ✅ Internationalization: Multilingual support is available. Add `X-Lang: "vi"` to the headers of request.
- ✅ Fix bugs

##### Version 1.2.0 (May 14, 2025)
- ✅ Added new `/products/*` API group to support distribution of new SimplifyTrip products (beyond eSIM) in the future.
- ✅ Upgraded `/orders` API. You can now place multiple products in a single order.
- ✅ Removed `/esims/*` API group, officially deleted on **June 15, 2025**.
- ✅ Updated webhook types when order processing completes: `ORDER_ESIM_SUCCESS` => `PURCHASE_ORDER_SUCCESS` and `ORDER_ESIM_FAIL` => `PURCHASE_ORDER_FAIL`
- ✅ Fix bugs

##### Version 1.1.0 (December 7, 2024)
- ✅ Added API to check eSIM status by ICCID
- ✅ Fix bugs

##### Version 1.0.0 (November 26, 2024)
- 📢 First official release of SimplifyTrip Open API
- ✅ Partner account provisioning
- ✅ One account can create multiple institutions
