# Order API



All endpoints require `Authorization: Bearer <secretKey>` and `X-Api-Key: <publicKey>`. Every POST also requires `Content-Type: application/json` and `X-Signature`, calculated from the entire request body using `checksumKey`. Recalculate the signature whenever the body changes. See [signature generation](/developers/signature). GET requests do not require `X-Signature`. Data is scoped to the institution and the API key's test/live mode.

<br />

**Order and return flow**

Create an eSIM or physical SIM order using `POST /api/v1/orders`; use `/orders/recharge` for data recharges. Save `orderId`, `trackId`, and each `subOrderId`. Look up `GET /orders/:id` or receive [webhooks](/webhooks) to track updates.

Order `status` is separate from return progress. Successfully delivered orders remain `SUCCESS` during and after returns. Track returns using `returnStatus`, `hasPendingReturn`, `hasRefundingReturn`, `refundAmount`, `items[].quantityReturned`, and `returns[]`. Only newly created physical SIM orders can be canceled; for successful orders, use the [Return Request API](/api-list/return-request).

## SIM data recharge API

Send a unique `trackId` and exactly one item containing `subTrackId`, a SKU of type `SIM_RECHARGE`, and `iccids` with 1–50 unique ICCIDs. Quantity is calculated from the ICCIDs; do not send `quantity`. China Telecom plans support only one ICCID. A successful response has the same structure as order creation, with `status: SUCCESS` for the order and item, and `type: SIM_RECHARGE`.

## Cancel order API

Only physical SIM orders with order status `NEW`, where all items are of type `SIM` and have status `NEW`, can be canceled. `orderId` is the SimplifyTrip order ID or `trackId`. `reason` is optional. Cancellation changes the order and items to `CANCELED` and refunds the full order amount to the wallet. Ineligible orders return 404.

## Errors and HTTP status

Successful GET requests return HTTP 200. POST requests currently return HTTP 201. Handle all successful 2xx responses. Validation errors or duplicate references may return 400; missing products/orders or orders ineligible for cancellation return 404; product, shipping, or wallet condition errors return 422; a busy system may return 503.
